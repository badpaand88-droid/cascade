# Проверка Cascade 0.4.0

Проверено на macOS с официальным sing-box 1.14.4:

- 16 схем (13 VLESS, AnyTLS, NaiveProxy HTTP2 и HTTP3): генерация, распознавание серверной конфигурации и экспорт устройств.
- 256 сочетаний схем: реальные два прокси-узла и локальный HTTP-ресурс, разные семейства IP на участках (IPv4 → IPv6 и IPv6 → IPv4).
- Для каждой одинаковой пары схем остановлен выходной узел: запросы перестают проходить, прямого обхода нет.
- Автоматический выбор: недоступный IPv4 и работающий IPv6.
- Серверные и клиентские конфиги проверены командами официального ядра, в том числе Windows-генератором.
- Повторная установка, смена конфига во время операции, откат и добавление устройства проверены на изолированном shell-стенде.
- Отдельная проверка rollback UFW: существующее IPv4-правило сохраняется после добавления и отката IPv6-правила UDP.
- QR/BPF, отсутствие приватного TLS-ключа в клиентских профилях, отклонение командных подстановок и некорректных IP.
- Интерфейс Mac: список всех схем, поля IPv6, появление полей сертификата при выборе AnyTLS.

В тестах TLS используется отдельный тестовый CA, явно доверенный только тестовому ядру. Проверка TLS не отключается. В рабочих настройках принимается доверенная цепочка сертификата для своего домена; самоподписанные сертификаты не предлагаются установщиком.

Запуск на реальных VPS для новой версии не выполнялся. Windows-приложение и установщик кросс-собраны на Mac: GUI, установка/удаление и TUN на Windows ещё требуют проверки. Импорт на физическом iPhone также не проверен.

Воспроизведение:

```sh
CASCADE_TEST_CORE=/path/to/verified/sing-box CASCADE_MATRIX_OUTPUT="$PWD/work/protocol-fixtures" swift test --disable-sandbox
python3 script/test_protocol_matrix.py /path/to/verified/sing-box work/protocol-fixtures --all-pairs
```

Windows-логика: `windows/Cascade.Tests`, переменные `CASCADE_TEST_CORE` и `CASCADE_MATRIX_OUTPUT` указывают на ядро и созданные Swift-тестом PEM-фикстуры.

Документация схем и ограничения: [PROTOCOLS.md](PROTOCOLS.md).
