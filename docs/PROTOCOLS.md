# IPv6 и схемы подключения — Cascade 0.4

Схема выбирается отдельно для участка «устройство → входной VPS» и участка «входной → выходной VPS». Можно использовать разные протоколы на этих участках. Ядро — официальный sing-box 1.14.4.

## Адреса

- Поле SSH принимает IPv4 или IPv6 без квадратных скобок. SSH-доступ может идти по IPv4, а VPN к тому же VPS — по IPv6.
- Дополнительные IPv4 и IPv6 должны принадлежать тому же VPS. Они не определяются автоматически: возьмите адреса в панели хостинга.
- «Только IPv4» / «Только IPv6» выбирает соответствующий адрес VPN.
- «Авто» включает все введённые адреса. JSON/BPF содержит URLTest, который проверяет их и выбирает доступный маршрут. Существующие TCP-сессии при отказе адреса могут прерваться; новый маршрут применяется к новым соединениям.
- На двух участках допускаются разные семейства адресов: IPv4 → IPv6 и IPv6 → IPv4, а также IPv4 → IPv4 и IPv6 → IPv6. Проверка SSH не подтверждает доступность VPN-порта.
- Для IPv6 нужны адрес и маршрут у провайдера VPS, поддержка IPv6 ОС, разрешённый порт в firewall хостинга и IPv6 в UFW. Установщик не меняет сетевые sysctl или firewall панели хостинга. Для двойного listener проверяется `net.ipv6.bindv6only=0`.
- Короткая ссылка/QR содержит один адрес. Для автоматического выбора IPv4/IPv6 используйте полный JSON или BPF.

## VLESS

В списке 13 защищённых вариантов:

- REALITY + TCP, с Vision или без Vision.
- REALITY + WebSocket, HTTP/2, gRPC, HTTPUpgrade.
- TLS + TCP, с Vision или без Vision.
- TLS + WebSocket, HTTP/2, gRPC, HTTPUpgrade, QUIC.

Vision используется только с обычным TCP. REALITY не применяется к QUIC. Путь WebSocket/HTTP/HTTPUpgrade и имя сервиса gRPC настраиваются в карточке схемы.

XHTTP, mKCP и DomainSocket в этом ядре не реализованы. Незашифрованный VLESS не предлагается для интернет-каскада. Поддержка конкретной схемы в других клиентах может отличаться; экспорт ориентирован на sing-box.

## AnyTLS и NaiveProxy

- AnyTLS поверх TLS.
- NaiveProxy через HTTPS/HTTP2.
- NaiveProxy через HTTP3/QUIC.

Для NaiveProxy установщик также устанавливает `libcronet.so` из того же официального Linux-архива с проверенным SHA-256. Windows-ядро извлекается вместе с `libcronet.dll`. В официальном клиенте Apple соответствующая поддержка включена.

## Домены и сертификаты

Свой домен не нужен только для вариантов REALITY: используется внешний TLS-сайт из дополнительных настроек.

Для обычного VLESS+TLS, AnyTLS и NaiveProxy нужны:

1. Ваш домен для каждого VPS (допускается один сертификат с несколькими SAN).
2. PEM-сертификат с полной цепочкой.
3. Соответствующий PEM-ключ без пароля.

Перед установкой проверяются соответствие домена, доверенная цепочка, совпадение ключа и срок действия не менее 7 дней. TLS-проверка не отключается. Установщик не выпускает и не обновляет сертификаты автоматически: обновление сертификата остаётся обязанностью владельца VPS.

Приватные TLS-ключи передаются по подтверждённому SSH и хранятся только в серверном конфиге с ограниченными правами. В клиентские JSON/BPF/QR они не включаются.

## Уже установленный каскад

«Получить конфиги» распознаёт протокол установленного каскада. Добавление устройства сохраняет прежние ключи и маршруты.

Повторная установка той же схемы обновляет адреса каскада и listener, сохраняя пользователей. Прямая смена протокола или TLS-имени существующей установки блокируется: старые профили перестали бы работать. Для этого нужна отдельная миграция; устанавливайте новую схему на свободной паре VPS.

## Проверка

На локальном стенде проверяются генерация и чтение конфигов, отдельные ключи устройств, отсутствие серверных приватных ключей в профиле, разные семейства IP, реальные соединения между ядрами и отсутствие прямого обхода при остановке выхода. Это не доказывает устойчивость к блокировкам в конкретной сети и не заменяет запуск GUI/TUN на Windows или импорт на физическом iPhone.
