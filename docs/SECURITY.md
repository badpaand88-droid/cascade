# Безопасность Cascade 0.5.0

Раздел доступен после установки или загрузки существующего каскада. Mac и Windows используют один серверный контроллер, передаваемый только через SSH с подтверждённым отпечатком. Пакеты устанавливаются из репозиториев ОС. Поддерживаются Ubuntu 22.04/24.04/26.04 и Debian 12/13.

## Как пользоваться

1. Загрузите существующий каскад и выполните сквозной тест.
2. Откройте «Безопасность серверов», выберите VPS, нажмите «Проверить безопасность».
3. Для перехода на ключ создайте или выберите приватный ключ Ed25519, задайте имя нового администратора и нажмите «Создать администратора с ключом». Если администратор уже существует, используйте «Проверить существующий вход».
4. Программа проверяет отдельное SSH-соединение по ключу и sudo. Сохраните ключ и имя администратора: они понадобятся при следующем запуске. Существующие пользователи не получают sudo автоматически. Новый администратор получает sudo без пароля для управления Cascade. Созданный приложением приватный ключ не имеет парольной фразы; файл защищён правами владельца (POSIX 0600 / Windows ACL).
5. Выберите нужные действия, нажмите «Применить выбранное». Неотмеченные пункты не изменяются. Для отключения ранее включённых настроек используется восстановление резервной копии.
6. Повторите для второго VPS. Смотрите результат каждой операции; не считайте обычное наличие установленного пакета проверкой защиты.

## Настройки

- SSH: запрет паролей и keyboard-interactive; запрет прямого входа root. Применяется только после входа отдельного администратора по ключу с работающим sudo. Проверяются синтаксис sshd и эффективные параметры текущего пользователя и root.
- UFW: IPv4/IPv6, разрешение фактического SSH-порта и VPN TCP/UDP, включение firewall. Другие правила и политика по умолчанию сохраняются: это не обещание закрытия всех посторонних сервисов. На выходном VPS можно поставить приоритетный запрет VPN-порта для всех, кроме адресов входного VPS. Укажите все действительные исходящие IPv4/IPv6 первого сервера, особенно при NAT. Программа проверяет каскад и откатывает изменение при потере связи.
- Fail2ban: SSH jail `sshd`, systemd journal, nftables-multiport, число попыток, окно наблюдения, длительность блокировки. В исключения добавляются фактический источник SSH-сеанса и адреса первого VPS. Существующие исключения сохраняются. Аудит показывает статус и заблокированные IP; отдельная кнопка снимает бан IPv4/IPv6. Правила для VPN-аутентификации не создаются: ошибки соединения не считаются автоматически атакой.
- Обновления: только security origins ОС через unattended-upgrades; автообновление индекса пакетов; без автоматической перезагрузки. Установка обновлений может перезапускать затронутые системные службы. Параметры обновления не распространяются на сторонние репозитории.

## Откат

Перед правкой конфигурации создаётся резервная копия SSH-фрагмента, UFW (IPv4 и IPv6), фрагмента Fail2ban и настроек обновлений. systemd запускает независимый от SSH таймер восстановления через 240 секунд. Он отменяется только после нового SSH-сеанса и сквозного HTTPS-теста через каскад. Контроллер использует общий lock с установкой/профилями Cascade. Если операция ещё удерживает lock, восстановление начинает работу после его освобождения. Установленные пакеты, созданный администратор и приватный ключ не удаляются при откате.

При потере связи дождитесь таймера, затем повторно подключитесь и запустите аудит. После перезапуска приложения аудит обнаруживает незавершённую транзакцию. «Восстановить настройки» возвращает последнюю резервную копию с проверкой SSH/VPN и своим таймером отката. Изменения тех же файлов, сделанные вручную после копии, будут отменены; это указано перед восстановлением. Не изменяйте эти файлы параллельно с работой Cascade. Firewall хостинга остаётся в его панели.

## Активное зондирование

Защита зависит от протокола, универсального переключателя нет.

- REALITY: маскировка реализована самим протоколом. Диагностика проверяет ответ TLS/HTTP без действительных данных REALITY; сайт и TLS-имя задаются в настройках соединения.
- Второй VPS: ограничение VPN-порта адресами первого VPS уменьшает поверхность внешнего зондирования (для обеих IP-семейств). Наличие и адрес первого VPS при этом не скрываются.
- «Проверить активное зондирование»: три TLS/HTTP-запроса с выбранного VPS к его собственному порту 443 — GET без авторизации, CONNECT без авторизации и CONNECT с неверным Basic-паролем. Сертификат проверяется системным CA; небезопасный TLS не включается. Результат — наблюдаемые ответы, а не оценка «невидимости». Проверка не эквивалентна внешнему сканеру и не охватывает QUIC/H2, все варианты некорректных VLESS/AnyTLS handshakes или поведение DPI.
- AnyTLS padding не является гарантией защиты от активных проб. В выбранном sing-box нет универсального fallback-переключателя для этого режима.
- Naive в sing-box не равен Caddy/HAProxy с HTTPS-сайтом и скрытой прокси-аутентификацией. В этой версии отдельный фронтенд не устанавливается: нельзя обещать такую маскировку для Naive/обычного VLESS TLS/AnyTLS. Её внедрение требует отдельной миграции с проверкой выдачи новых устройств и обновления сертификатов.
- Fail2ban дополняет защиту SSH, но не маскирует VPN и не заменяет протокольную защиту.
