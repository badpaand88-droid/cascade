# Cascade для Mac · 0.3.0

Локальное приложение на SwiftUI: вводите SSH-доступы к двум VPS, проверяете серверы, устанавливаете VLESS + REALITY + Vision и сохраняете профиль sing-box. Собственный домен и сертификат не требуются.

## Запуск

1. Распакуйте `Cascade-Mac.zip` и откройте приложение Cascade из архива. Можно перенести приложение в «Программы».
2. Введите IPv4, SSH-порт, логин и пароль либо выберите приватный ключ. Для зашифрованного ключа укажите его пароль.
3. Получите SSH-отпечатки и сравните их с ключами в консоли/панели хостинга.
4. Нажмите «Проверить серверы». На Mac скачивается официальный sing-box 1.14.4; SHA-256 сверяется с зафиксированным хешем официального релиза.
5. Нажмите «Установить на оба сервера». Сначала настраивается выходной сервер, затем входной.
6. Дождитесь сквозного теста, сохраните JSON и импортируйте его как локальный профиль в клиент sing-box 1.14.4. Для работы VPN разрешите системное VPN-подключение.

Mac: Apple Silicon, macOS 14 или новее. Сборка подписана локальной ad-hoc подписью, без Developer ID и нотариализации Apple. Это локальная тестовая версия, не готовый публичный релиз для массового распространения. Для Intel можно пересобрать из исходников; эта сборка на Intel не проверялась.

## Новое в 0.3

- Если оба SSH-подключения уже проверены с подтверждёнными отпечатками, отдельный шаг проверки отпечатков пропускается. Кнопка меняется на «Подготовить установку». Изменение доступов сбрасывает доверие и результаты.
- «Получить конфиги» читает существующий Cascade с двух VPS, восстанавливает профили устройств и выполняет проверку. Повторная установка не нужна.
- «Создать профиль» добавляет отдельный UUID на входной сервер. Прежние пользователи, REALITY-ключи и маршрут через второй сервер сохраняются. Сервис входного VPS кратко перезапускается; обновление выполняется отдельной задачей, способной пережить разрыв управляющего SSH. Приложение ждёт подтверждения результата после восстановления связи.
- Повторная установка загруженного существующего каскада сохраняет полный конфиг со всеми устройствами.
- Для выбранного устройства доступны JSON, прямой локальный импорт BPF в SFM и QR в форматах VLESS-ссылки и полного JSON. VLESS/JSON-QR поддерживается не всеми клиентами; для официального SFM используйте BPF или JSON-файл. Облачная ссылка и публикация ключей на сервере не создаются.
- Панель «sing-box для Mac» обнаруживает установленный клиент. Если его нет, скачивает официальный SFM 1.14.4 под архитектуру Mac, сверяет SHA-256, проверяет подпись pkg и доверие macOS, затем открывает системный установщик. Пароль администратора и разрешение сетевого расширения вводятся/подтверждаются в системных окнах самим пользователем.

Чтобы работать с уже установленным каскадом: введите прежние доступы → проверьте SSH каждого VPS → нажмите «Получить конфиги». Для ещё одного устройства укажите имя и нажмите «Создать профиль», затем выберите JSON, импорт в SFM или QR. Установка каскада заново не требуется.

Ubuntu 26.04 разрешена с версии 0.2.1. Для запуска 0.3.0 закройте старый экземпляр Cascade; доступы хранятся только в его памяти и потребуется ввести их повторно. Работающий клиент sing-box и серверные сервисы от закрытия Cascade не останавливаются.

## Новое в 0.2

В каждой карточке есть отдельная кнопка «Проверить подключение»: она проверяет SSH-аутентификацию именно этого сервера, не требуя доступов ко второму и не меняя настройки VPS. При первом обращении нужно сверить и подтвердить SSH-отпечаток. Успешный результат зажигает значок над карточкой; при ошибке он становится красным. Изменение IP, порта, логина или доступа сбрасывает проверку.

После двух успешных SSH-проверок становится доступна кнопка «Проверить связь между VPS». Она с первого сервера пробует открыть TCP-соединение к SSH-порту и порту 443 второго. Достаточно одного доступного порта; в подписи показывается, какие порты ответили. Зелёная линия до установки означает эту TCP-доступность. После установки она показывает результат настоящего сквозного теста VPN. До установки VPN-туннеля ещё нет. Статусы показывают результат последней проверки, а не постоянное фоновое соединение; время проверки указано рядом с результатом.

В панели «Дополнительные настройки» кнопка «Проверить TLS-сайт» проверяет TLS 1.3 и доверенный сертификат выбранного имени с уже проверенных по SSH VPS. Если доступен только один — проверяется с него; если ни одного — только с Mac. Область проверки явно указана в результате. Успешный TLS-тест не доказывает совместимость конкретного сервера с REALITY и доступность VPN у оператора.

Добавлены анимация проверки, подсветка узлов/линии и иконка macOS, отрисованная по исходному знаку. При включённом уменьшении движения в macOS непрерывная анимация отключается.

## Требования к VPS

- Два разных IPv4-адреса. Первый VPS — входной, второй — выходной.
- Ubuntu 22.04/24.04/26.04 либо Debian 12/13, systemd, x86_64 или ARM64.
- SSH-пользователь root либо пользователь с `sudo -n` без пароля.
- Чистые VPS, свободный TCP-порт 443; на базовой системе должны быть `ss` (iproute2), `openssl`, `timeout`, `flock`, `tar`, `base64`, `sha256sum`.
- Доступ к GitHub с Mac и обоих VPS, доступ к выбранному внешнему TLS-сайту с TLS 1.3. По умолчанию `www.microsoft.com`, можно поменять в дополнительных настройках.
- В панели хостинга разрешите TCP 443 на входной сервер из своей сети и на выходной — с входного VPS. Если используется NAT, учитывайте реальный исходящий IP входного сервера.

## Что меняется на серверах

- Отдельный сервис `bp-cascade.service`, пользователь и группа `bp-cascade`.
- Бинарник `/opt/bp-cascade/sing-box-1.14.4` из официального архива, проверенного по SHA-256.
- Конфиг `/etc/bp-cascade/config.json` (root:bp-cascade, 0640), служба запускается от непривилегированного пользователя с правом слушать порт 443.
- В активный UFW добавляются правила TCP 443: входной — общий доступ; выходной — с IP входного сервера. UFW не включается, не сбрасывается; правила SSH не меняются. Внешний firewall хостинга приложение не управляет. Другие правила nftables/iptables могут блокировать соединение.
- При необходимости устанавливаются curl и ca-certificates через apt. Общесистемное обновление пакетов не запускается.

Клиент знает только входной сервер. Входной направляет весь прокси-трафик через выходной, прямого резервного выхода нет. Никакой веб-панели или открытого SOCKS-прокси на VPS нет. Секреты не печатаются в журнал приложения.

## Проверка и повторный запуск

До установки проверяются ОС, права, SSH-ключ, порт, TLS-сайт; все конфиги проходят `sing-box check`. На Mac после установки временно запускается SOCKS-прокси на loopback и выполняются HTTPS-запросы через оба узла к `api.ipify.org` и `www.cloudflare.com`. На системный VPN этот тест не переключает. Если другой VPN уже включён, он может повлиять на доступность цепочки.

Успех означает доступность этих ресурсов из текущей сети Mac. Он не доказывает работу из мобильной сети, работоспособность всех приложений, отсутствие утечек в системном TUN или будущую устойчивость к блокировкам. Фактический импорт и системный TUN в клиентах macOS/iOS/Android ещё не проверены.

Если сквозной тест не прошёл, приложение показывает предупреждение, позволяет повторить тест и сохранить явно помеченный как непроверенный конфиг. Установленные сервисы в этом случае остаются на VPS для диагностики. Если показанный выходной IP отличается от адреса второго VPS, проверьте NAT/маршрутизацию у хостинга.

Повторная установка этой же пары сохраняет UUID, REALITY-ключи и short ID. Подмена пары серверов, другая роль или изменение конфигурации после проверки останавливают установку. При повторной установке нужно указать прежний TLS-сайт.

## Откат

Перед заменой сервиса создаётся `/etc/bp-cascade/backup.<идентификатор>/rollback.sh`. При ошибке выполняется попытка отката именно текущей операции на обоих узлах; старые успешные установки не откатываются из-за сбоя новой попытки. Если SSH недоступен, приложение честно показывает, что откат не подтверждён, и предлагает повторить его.

После успешной установки есть кнопка «Откатить…». Для ручного восстановления по SSH используйте root/sudo и запустите `bash /etc/bp-cascade/backup.<нужный идентификатор>/rollback.sh`. Путь последней точки записан в `/etc/bp-cascade/last-backup`. Восстанавливаются прежние конфиг, служба и состояние автозапуска, удаляются добавленные этой операцией правила UFW. Установленные зависимости, бинарники, системная учётная запись и история откатов сохраняются. Это откат настройки, а не полное удаление пакетов.

## Доступы и конфиденциальность

Пароли не записываются в настройки, Keychain, аргументы команд или журнал: SSH получает их через отдельный askpass-процесс и его окружение. Они остаются в памяти до закрытия приложения или сброса доступа. Приватный SSH-ключ читается системным OpenSSH из выбранного файла.

Рабочие конфиги и вывод команд могут временно содержать секреты: они помещаются в каталоги 0700 и файлы 0600 и удаляются после операции. Принудительное завершение процесса может оставить временные файлы до очистки macOS. При передаче BPF в SFM приватный временный файл сохраняется до 5 минут, чтобы клиент успел его прочитать, затем удаляется, если Cascade продолжает работать. QR PNG сохраняется с правами 0600; скопированная пользователем ссылка/JSON остаётся в системном буфере обмена. Конфиги на VPS и точки отката хранят необходимые серверные ключи. Экспортированный JSON — ключ доступа к VPN, храните его как пароль.

Регистрации, нашей облачной инфраструктуры, аналитики и загрузки доступов к третьим лицам нет. Сетевые обращения: SSH к вашим VPS, GitHub для официального ядра, TLS-сайт REALITY и два HTTPS-сервиса проверки. Они видят обычные сетевые метаданные соответствующих обращений.

## Что проверено

- Swift-сборка и запуск окна на этом Mac.
- Валидность всех конфигов настоящим sing-box 1.14.4.
- Локальный сквозной тест двух настоящих REALITY + Vision узлов; при остановке выходного узла соединение прекращается.
- Сценарии установки, повторной установки, сохранения ключей, отката, ошибки запуска, занятого порта и изменения конфига — в изолированном файловом стенде с подменёнными системными командами.

Пользователь выполнил установку 0.2.1 на двух VPS: активный профиль SFM, TCP-соединения к входному серверу и внешний IP выходного сервера были проверены. Новые операции 0.3 (добавление устройств, BPF-импорт и установка SFM) проверялись отдельно; добавление устройства на реальные VPS в этой сессии не запускалось. В файловом стенде команды systemd/UFW имитируются.

## Исходники и сборка

В `Cascade-source.zip`: SwiftPM-проект, тесты и скрипт `script/build_and_run.sh`. Команда `./script/build_and_run.sh --package` создаёт приложение и ZIP; без параметров — собирает и открывает приложение. Загружаемых зависимостей SwiftPM нет; используется системная zlib. Для разработки нужны Xcode и Swift 6.

Ядро sing-box и пакет SFM не вложены в архив приложения: скачиваются из официального релиза. Для сжатия локального BPF используется системная zlib, сторонних SwiftPM-зависимостей нет.
